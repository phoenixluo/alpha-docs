# 地址预处理

客户填的地址常常不规范——少个门牌、写成地标、拼错路名。**配送 → 地址预处理** 就是
把这些地址整理成能落到地图上的坐标。

**没有坐标的地址，排不进路线，也不会出现在轨迹地图上。** 这一页的意义就在这儿。

## 三个页签

页面按处理状态分三组，每组标题上带数量：

| 页签 | 意思 |
|---|---|
| **待处理** | 还没处理的，默认看这一组 |
| **已处理** | 已经解析出坐标的 |
| **已核实** | 人工确认过的 |

顶部搜索框按地址关键词找。筛选条件会写进网址，方便分工时把某一组发给同事。

## 处理一条地址

1. 在列表里点开一条，右边是 **编辑地址**。
2. 把地址补完整、改对。
3. 点 **解析坐标**，系统把文字地址转成经纬度，成功会提示**地址已解析**。
4. 保存，提示**地址已更新**。

## 在地图上微调

右边地图会把待处理的点标出来。**待处理的点可以直接拖动**来校正位置——鼠标移上去会
提示可拖动调整。点标记可以看到这条地址的详情。

自动解析的结果落偏了，用拖动比反复改文字快。

## 常见情况

| 现象 | 处理 |
|---|---|
| 解析失败 | 地址信息不足。补上区、市、邮编再试 |
| 解析到了但位置明显不对 | 在地图上拖到正确位置 |
| 同一个客户反复要改 | 在 **合作伙伴 → 寄件人账户** 里维护好常用地址，从源头解决 |

:::note 接口推进来的运单
通过接口建单时，系统**不会替你猜坐标**——报价和排线要求地址带坐标。详见
[开发者指南的地址解析章节](/tms/address)。
:::
