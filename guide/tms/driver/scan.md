# 司机扫码

司机不用后台系统，用手机浏览器打开的**包裹扫描器**。一个页面，就干一件事：
扫包裹、记状态。

## 登录

打开扫描地址，看到 **移动扫描登录**，输入**电子邮件**和**密码**，点 **登录**。

账号由管理员在 **设置 → 团队成员** 里建好发给司机，不是司机自己注册的。

登录后顶部显示 **包裹扫描器** 和当前账号，右上角可以退出。

## 扫一件货

```mermaid
flowchart LR
    a["1 选事件类型"] --> b["2 扫码或手输"] --> c["3 提示扫描成功"]
```

**顺序不能反**——先选事件类型，再扫。没选类型就扫，会提示**请选择事件类型**。

1. 在 **选择事件类型** 下拉里选这次扫的是哪一步：取件、入库、分拣、出库、配送……
2. 点 **扫描包裹 → 启动摄像头扫描器**，把镜头对准条码。识别到会显示
   **已检测到：单号**。
3. 扫不了就用下面的 **手动输入运单号**，输完回车提交。
4. 成功显示 **扫描成功**。

扫完一件接着扫下一件，事件类型不用重选。

## 位置会一起记下来

页面会取手机的定位，和扫描记录一起存。首次使用浏览器会弹窗询问定位权限——**要允许**，
拒绝了扫码仍然能用，但这条记录就没有位置。

## 下拉里只有一两项？

**事件类型下拉是按权限过滤的。** 只给了取件权限的人，下拉里就只有取件。

这是故意的：分拣员不应该能标"已送达"。需要更多类型找管理员在 **设置 → 团队成员**
里调整权限。

## 摄像头打不开

| 提示 | 原因和处理 |
|---|---|
| 浏览器不支持条码识别 | 换 Chrome 或 Edge 打开 |
| 无法访问摄像头 | 在浏览器设置里允许本站使用摄像头 |
| 扫描器初始化失败 | 刷新页面重试 |

摄像头始终不行也不耽误干活——用**手动输入运单号**照样能提交。

## 这里不做送达确认

扫描页只记状态，**不拍照、不做签收凭证**。签收凭证（POD）走 LINE，是另一条路径，
见[送达确认](./pod)。
